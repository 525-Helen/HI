## 二、各版本结果

### V1
- 生成并导出**三餐卡路里管家 100 条完整评测报告**（`aadb14d`）。
- 首版独立留出集验收：**严格通过率 80%，含部分通过率 90%**（`cc19bda` / `570a9c8`），据此定位出「日期解析」「过敏」两类缺陷待修复。

### V2
- 相对日期统一解析（昨天/上周X/N天前/上个月）与跨月修复、request_id 贯穿意图/澄清/计算/保存/重试；`save_meal_record` 增加 `idempotency_key` 幂等防重。
- 留出集 v2 验收 001–010 通过；011–020 因账户余额欠费未执行（`acd6b9d`）。

### V3
- 修复两个 P0 缺陷：① 无食物上下文臆造拦截（SP 强化）；② 中文数字「两」日期解析统一。
- 留出集 20 条验收：**17/20 严格通过（85%）**；失败 005/006/017，020 幂等验证通过（`6668af9`）。

### V4
- 独立留出集 20 条**全量回归 20/20 严格通过**，恢复中性档案（`b128fef`）。
- 交付中确认两项能力：V4_005 生活化份量承接（普通碗·八成满→映射克数）、V4_011 low_calorie 不阻断保存。

### V5
- 全新独立留出集 20 条：**17 严格通过 + 3 部分通过**（`5a91530`）。
- 修复三缺陷：① 可数食物与生活化容器份量映射（"一根香蕉""普通纸杯·装得比较满"→portion_desc 估算）；② 保留安全规则（不臆造/拒绝估算零泄露/过敏精确匹配/warning 不阻断保存）；③ 知识库补充「乳制品过敏者早餐高蛋白替代方案」及权威来源（`78957a0`、`d90ab43`）。
- 修复后**完整回归 20/20 严格通过**（`a7d6187`）。

### V6（产品化收尾，2026-10-20 完成）
作废不改变核心业务规则，新增：
1. 请求级审计日志（request_id/意图/工具及参数/耗时/错误类型/原始返回摘要）；
2. 运行指标（工具失败率、平均耗时、按请求聚合、save_count）；Token/调用成本明确标记未接入；
3. 用户画像新增/修改/删除（`delete_user_profile`）与「纠错以最新确认信息为准」；
4. 知识库来源真实性校验（无依据如实拒答，禁止编造来源/数据）。
回归 **V5_006 / 011 / 014 / 015 / 019 / 020 六条 6/6 严格通过**，防臆造/过敏拦截/日期一致/拒绝估算/幂等防重均保持（`9d01905`、`a8e199b`）。

## 三、贯穿性指标（V5/V6 关键口径）
- 日期一致率：100%（相对日期在计算端单次解析并全程复用，落库日期与计算端一致）。
- 过敏：精确优先匹配，不误拦同类（如登记海带不拦虾）；V6 回归过敏召回/不误拦均通过。
- 拒绝估算热量泄露率：0%。
- 幂等防重：同一请求级 request_id 重试不重复落库（`uq_meal_request_id` 唯一索引兜底）。
- 知识来源：答案必须能被 `sources` 支撑，无据此如实拒答。
